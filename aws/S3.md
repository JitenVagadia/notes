# Amazon S3
* main stuff
* infinitely scaling storage
* Use cases: backup & storage, DR, app hosting, media hosting, data lakes, software delivery, static website
* Buckets - "directories" to store objects (files), region level
  * Naming
    * Shared Global Namespace - globally unique
    * Account Regional Namespace - allows to "reuse" same bucket name across regions
    * no uppercase, no underscore, no ip, no xn-- prefix, no -s3alias suffix,only lowercase/number prefix
* Objects - have a key
  * s3://my-bucket/imaginary_folder/abc/my_file.txt
    * bucket : my-bucket
    * prefix : imaginary_foler/abc/
    * object name : my_file.txt
  * if uploading bigger than 5G, must use multi part upload
  * Version ID
  * metadata (key value pairs, system/user metadata)
    * if user defined, then prefix x-amz-meta
    * not searchable
  * tags (key value pairs, at max 10, helps with security/lifecycle)
    * useful for fine grained permissions, analytics
    * not searchable
* Security
  * user -> IAM
  * resource ->
    * bucket policies: bucket wide rules, also json based like(resource, effect,action,principal), also cross account
    * object access control list - finer grain (can disable)
    * bucket access control list - not common (can disable)
  * can encrypt objects with encryption key
    * Server side
      * s3 managed - enabled by default
        * using header "x-amz-server-side-encryption": "AES256"
      * KMS
        * using header "x-amz-server-side-encryption": "aws:kms"
        * more user control
      * customer provided
        * HTTPS must be used, encryption key in header, aws doesn't store the key
    * client side
    * can enforce https in bucket policies using condition field
  * CORS - sort of a browser security feature, made standard
    * script of one site should not be able to call another
      * done by browser, browser first asks the target site using exposed /options at the target
    * calls to s3 bucket from browser -> need to enable cors (static website enabled)
  * MFA delete
  * S3 Access Logs -  access logs logged to another bucket
  * Pre signed URLs
    * generate using S3 console, CLI, SDK
    * inherit the permissions of a user that generated it
  * S3 Access Points
    * simplify access control
    * has its own dns name
    * has a access point policy, similar to bucket policy
    * (EC2 instance -> VPC Endpoint ) in VPC -> (Access point VPC Origin) -> (S3 bucket)
* S3 Object Lambda
  * setup: (s3 bucket) -> (standard s3 access point) -> (S3 object lambda access point)
* Static website hosting
  * "http://bucket-name.s3-website-aws-region.amazonaws.com"
  * 403 forbidden -> bucket doesn't have public access
* Versioning, Enabled at bucket level
* Replication
  * bucket to bucket
  * versioning has to be enabled on all
  * cross region, same region (CRR,SRR)
  * even cross account
  * when enabled, only new are replicated, need to do batch replication for existing
  * not transitive for some reason
* storage classes
  * moved between by s3 lifecycle config, or manually
  * transition actions - like move after 60 days since creation, etc.
  * expiration actions - like delete old versions, incomplete downloads, old files
  * can create rules for any prefix or tag
  * S3 Analytics - helps deciding for standard - standard IA, report updated daily
* S3 Event Notifications
  * S3:ObjectCreated, S3:ObjectRemoved, S3:ObjectRestore, S3:Replication
  * generally delivered in seconds, may take a minute+ though
  * to maybe SNS, SQS, Lambda, (they need to allow access in resource policy)
  * to event bridge, advanced filtering, multiple destinations, archive, replay, reliable delivery
* S3 Baseline perf
  * 3.5K write TPS, 5.5k read, both per prefix in a bucket
  * 100-200ms latency
  * multipart upload, should do over 100M, must for over 5G
  * S3 transfer accelaration - transfer file to an aws edge location first, which will forward the data to the s3 bucket in target region
  * can do parallel (/get)s for different parts of file based on byte range
